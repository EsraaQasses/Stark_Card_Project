# Stark Card — تقرير الأولوية الأولى، 27 أكتوبر 2026

توقّف العمل عند الأولوية الأولى. لا Push أو Merge أو Deploy، ولا تعديل لملفات Expo أو الأسرار أو قاعدة بيانات التطبيق. توجد تعديلات محلية أخرى سابقة/متزامنة؛ لم يتم إلغاؤها أو نسبتها إلى هذا العمل.

## ملفات هذا العمل

داخل admin:

- src/App.jsx: مسار إضافة طريقة الدفع.
- src/components/PaymentMediaFields.jsx: حقلا QR والصورة الإرشادية المشتركان والمعاينة والتحقق.
- src/components/Payments.jsx: ربط الحقول وطلب الحفظ والعرض وإصلاح مساري imports.
- src/pages/Dashboard/Payments.jsx: الحقول والحفظ والعرض وفتح نموذج الإضافة من المسار.
- src/pages/Requests/ShippingRequests.jsx: توقيت عرض التاريخ فقط؛ بقية التعديلات الموجودة كانت سابقة.
- src/pages/Users/CustomerDetails.jsx وsrc/pages/Users/AgentDetails.jsx: تحقق ورسائل وحدود سبب تعديل الرصيد.
- test_priority_one.py وrun_priority_one_checks.py: اختبارات Regression وتشغيل مع قاعدة ذاكرة معزولة.
- priority-one-checks.log وpriority-one-shipping-recheck.log: نتائج التشغيل الفعلية.
- PRIORITY_ONE_REPORT.md: التقرير والتسليم.

داخل النسخة المجاورة Stark_Card_Project-backend-v2/stark_backend، بعد الموافقة على الكتابة خارج workspace:

- all_requests/filtering.py: إضافة رقم السجل للبحث في مجموعات فلاتر الشحن.
- payment_methods/models.py: instruction_image اختياري nullable.
- payment_methods/serializers.py: قراءة/حفظ/تحقق instruction_image ضمن آلية الملفات الموجودة.
- payment_methods/media_service.py: حماية الملف من الحذف إن بقي مرجع إليه.
- payment_methods/views.py: تنظيف الصورة عند حذف سجل الدفع، وقيمة null للطريقة الثابتة agent-shipping.
- payment_methods/migrations/0010_paymentmethod_instruction_image.py: Migration واحدة جديدة لهذا العمل، تعتمد على 0009 الموجودة محلياً.
- users/services/customer_admin.py: سبب تعديل الرصيد من 1 إلى 500 حرف، مع بقاء صلاحيات الأدمن وidempotency وآلية التسوية الحالية.

## التحقق وحدوده

- npm run build النهائي: ناجح؛ تحذير حجم بعض chunks فقط وتحذير توقيت plugin.
- Django system check: ناجح.
- makemigrations --check --dry-run: لا تغييرات غير ممثلة بـMigration.
- تم تطبيق 0010 بنجاح مع بقية migrations على قاعدة اختبار SQLite مؤقتة في الذاكرة فقط.
- التشغيل الأول: 39 اختباراً، نجح 38 وفشل اختبار البحث برقم طلب الشحن؛ كشف عيب Backend الذي أصلح لاحقاً. تتضمن المجموعة اختبارات الصور الموجودة الموروثة والمستوردة، لذلك العدد ليس عدد حالات فريدة جديدة.
- يغطي تعديل الرصيد العملاء والوكلاء وUSD/SYP و«إيداع» و«شحن» والرموز الخاصة و500 حرف ورفض الفارغ والمسافات و501 حرف، مع إعادة الطلب والتحقق من تغير الرصيد مرة واحدة فقط.
- يغطي الوسائط إعادة فتح السجل وقراءة المستخدم والصلاحيات واستبدال/حذف الصورة الإرشادية وعدم تغيير QR وطرق الدفع القديمة ورفض ملف مزيف، إضافة لاختبارات الصور والمعرض الموجودة.
- بعد إصلاح البحث: نجحت الاختبارات التسعة المعادة (الحالة الجديدة على مصدري standard وagent-admin وثمانية اختبارات عقد الشحن الموجودة)، خلال 3.908 ثانية بعد إعداد قاعدة الاختبار. التفاصيل في priority-one-shipping-recheck.log. لم تُعد المجموعة الكاملة لأن التغيير اللاحق اقتصر على فلتر الشحن.
- هذه طلبات API محلية فعلية عبر DRF APIClient وقاعدة اختبار، وليست Mock Data. لم يُشغّل HTTP server ولم يُجرَ تحقق تفاعلي في المتصفح أو اختبار تطبيق Expo.
- SQLite لا يثبت سلوك التزامن والأقفال في PostgreSQL؛ تدقيق الصرف المزدوج والرصيد السالب والدقة المالية الكاملة ضمن الأولوية الثانية المؤجلة.

## تسليم Expo — لا تعديلات عليه

- API الإدارة: /api/payment-methods/admin/payment-methods/ وللسجل /{id}/. multipart يدعم icon_url وqr_image وinstruction_image؛ عدم إرسال الحقل يحافظ عليه، وإرسال قيمة فارغة يحذفه. JSON PATCH بقيمة null يحذفه أيضاً.
- API المستخدم: GET /api/payment-methods/user/payment-methods/ يعيد روابط الصور الثلاثة المستقلة وadditional_images؛ instruction_image قد يكون null للطرق القديمة ولطريقة agent-shipping.
- app/src/screens/Payment.js: تمرير qr_image وinstruction_image عند بناء/نقل كائن طريقة الدفع إلى شاشة التفاصيل، دون استبدال أحدهما بالآخر.
- app/src/screens/payments/ShippingMethodInfo.js: الإبقاء على الحقلين عند تطبيع parsedMethod؛ عرض QR الفعلي للدفع في موضعه، ثم قسم مستقل بعنوان «كيفية مسح QR وإرسال الأموال» يعرض instruction_image فقط عند وجوده. استخدام أبعاد الصورة أو resizeMode="contain" للحفاظ على المحتوى. غياب الصورة لا يمنع الدفع.
- لا تغيير مطلوب لحد السبب في شاشات تحويل Expo حسب البحث الحالي؛ شرط 10 أحرف المعني كان في Admin وخدمة تعديل الرصيد، وليس قاعدة عامة لكل note/reason.
