# Stark Card Admin — إتمام التكامل المحلي

التاريخ: 29 أكتوبر 2026. الفرع: `frontend-v2`. استكمال للعمل السابق دون إعادة تعيين Git أو تطبيق/حذف Stash. قرئ تقرير Backend المؤرخ 27 أكتوبر كاملاً قبل التنفيذ.

## النتيجة

التكامل المحلي مكتمل ضمن العقود الموثقة، مع اجتياز البناء والفحوص أدناه. لم يحدث Commit أو Push أو Merge أو Deployment. لم تُستخدم API الإنتاج للكتابة أو تُنفذ عملية شراء/تحويل حقيقية. التغييرات المتزامنة في Expo وBackend محفوظة ولم تُعدّل ضمن هذا الاستكمال.

## ما تغير

- طرق الدفع: تفعيل العملة والوصف وحفظهما؛ إرسال USD/SYP بالقيم المعتمدة؛ حفظ الملفات الثلاثة مستقلة؛ الحذف عبر JSON PATCH بقيمة null؛ تعديل جزئي يحافظ على الصور غير المتغيرة.
- المعرض: إضافة على دفعات حتى 10 ملفات؛ حد 20 صورة؛ استبدال الصورة عبر PATCH مع الاحتفاظ بمعرّفها؛ حذف وترتيب عبر المسارات الموثقة. تحفظ الواجهة حالة الخطوات المكتملة عند فشل خطوة لاحقة. عند انقطاع الاتصال غير المؤكد تمنع إعادة الحفظ حتى العودة للقائمة وتحديث السجل لتجنب تكرار الرفع.
- توحيد محرر الدفع القديم مع صفحة الدفع الحالية بدلاً من إبقاء تنفيذين مختلفين للعقد نفسه. رسائل فشل الحفظ تظهر داخل المحرر أيضاً.
- الشحن: العدادات والمبالغ من summary المفلتر قبل Pagination؛ فصل USD وSYP وحالات الطلب؛ إضافة فلتر العملة ومعرّفات المستخدم والوكيل والمراجع والمزوّد وحدود المبلغ والترتيب. توضيح معنى user في agent-admin. ترتيب القائمة المجمعة يتبع الاختيار. الاعتماد والرفض يستخدمان POST update_status فقط؛ لا كتابة عامة على سجل الشحن.
- فئات العملاء: الحفاظ على مسار assign-category وإعادة قراءة العميل بعد الحفظ، مع معالجة رسائل الخطأ المنظمة.
- المزوّدون: الحفاظ على deletion-preview وretire؛ منع المزامنة للمزوّد المعطّل في الواجهة. فتح محرر المنتج يقرأ الكتالوج المحفوظ ولا يشغّل مزامنة تلقائية.
- المنتجات: حقل product_profit_percentage الحقيقي، دون معادلة تسعير في Admin؛ عرض تعطيل المزوّد/المنتج الخارجي وتعطيل الإدارة وخطأ المزامنة السابق. التعديل يستخدم PATCH ولا يعيد إرسال الربط غير المتغيّر، حتى يمكن تعديل منتج مرتبط بمنتج خارجي معطّل.
- Home: إصلاح إزاحة شهر في buildMonthAnchors. النافذة الآن سبعة أشهر تنتهي بالشهر الحالي. بقيت Operational Logs وبطاقات الطلبات pending/in-progress محذوفة. حفظ النص العربي وUTF-8 بعد التحقق من diff.
- transition: الحفاظ على مجاميع حجم حركة السجل منفصلة حسب العملة، وتصدير مبلغ السجل الأصلي مع UTF-8 BOM؛ تصحيح شرح منفذ العملية لعدم نسبته تلقائياً إلى صاحب المحفظة.
- finance-controls: استخدام تقرير Backend ولقطاته دون تسعير محلي؛ استكمال تسميات transfers وshipping_credits وcashouts وcompensations وcommission_reversals؛ معالجة أخطاء التقارير المنظمة دون عرض كائن داخل React.
- معالجة أخطاء مشتركة تعرض fields في غلاف Backend، وتستبعد code وmeta/request_id من رسالة المستخدم.

## اختبارات فعلية

### المتصفح وHTTP المحلي

استخدم Admin على 127.0.0.1:5179 وBackend على 127.0.0.1:8017. قاعدة SQLite وملفات الصور في مجلد Temp مستقل؛ لم تستخدم قاعدة Backend المحلية الأصلية لهذه الكتابات. استُخدم حساب integration-admin مؤقت، وحُذف ملف جلسة المتصفح المولد عند الإنهاء.

| الحالة | النتيجة المرصودة |
|---|---|
| إنشاء طريقة دفع SYP بوصف وصورة رئيسية وQR وصورة تعليمات ومعرض | POST 201؛ إضافة المعرض 201 وترتيبه 200 |
| إعادة فتح طريقة الدفع | العملة والوصف والصور محفوظة |
| استبدال QR وصورة معرض | PATCH 200؛ بقي معرّف صورة المعرض نفسه |
| حذف الصور الثلاثة والمعرض ثم إعادة القراءة | icon_url/qr_image/instruction_image = null؛ additional_images = [] |
| حذف سجل الدفع التجريبي كاملاً | HTTP DELETE 204 ثم GET 404؛ حذف السجل كاملاً تحقق عبر HTTP، لا يُنسب إلى نقرة متصفح ناجحة |
| فلتر USD وإجماليات الشحن | صفوف وsummary مفلتران؛ ظهور 12.34 USD و5000 SYP منفصلين لكل مصدر في البيانات الأولية |
| اعتماد طلب agent-admin | POST /shipping/agent-admin/1/update_status/ أعاد 200 |
| تغيير فئة العميل | assign-category أعاد 200؛ ظهرت Integration category ونسبة 5.00 بعد إعادة التحميل |
| Home | الإيراد الكلي واليومي 20 USD و1000 SYP؛ بعد الإصلاح ظهرت Apr–Oct دون Nov في عينة أكتوبر |
| finance-controls | الإيراد 20/1000، التكلفة 12/600، الربح الإجمالي 8/400، العمولة 2/100، الصافي 6/300؛ الترتيب USD/SYP |
| transition | خمسة سجلات معتمدة؛ حجم الحركة 34.34 USD و1100 SYP، وليس صافي ربح أو حجم تحويلات فريد |
| CSV من زر التصدير | ستة أسطر: عنوان وخمسة سجلات؛ عمود للعملة؛ بايتات BOM هي 239,187,191 |
| فتح منتج مرتبط بمزوّد معطّل | ظهرت عدم الإتاحة وتعطيل الإدارة والخطأ TEST_OUTAGE؛ لم يُرسل sync_products |
| حفظ نسبة ربح المنتج | كشف PUT القديم رفض الربط المعطّل 400؛ بعد الإصلاح PATCH 200، وإعادة القراءة أكدت 4.25 مع بقاء external_product=1 وapi_config=1 |

المجموعات متداخلة؛ لا تجمع أعدادها باعتبارها حالات فريدة. اختبارات مزامنة/شراء المزوّد تستخدم موصلات محاكاة داخل الاختبارات؛ لم يُختبر اتصال حقيقي بعلاء الدين أو Stark-Card، ولم ينفذ شراء حقيقي. بعض tracebacks في السجل أخطاء مخزّنة/تدقيق محقونة عمداً للتحقق من rollback.

تشغيل PostgreSQL أنشأ cluster مستقلاً على المنفذ 55447؛ عولج تعليق pg_ctl على Windows بتوجيه مخرجاته إلى ملف بدلاً من PIPE. جميع اختبارات التشغيل النهائي نجحت، ثم أوقف cluster مع keepdb. قواعده وملفاته محفوظة في Temp/stark-admin-pg-z6j55y_v. محاولة التشغيل الأولى محفوظة أيضاً في Temp/stark-admin-pg-t59aomul ومتوقفة. الخدمة الأصلية لم تُعدّل، ولم تحذف قاعدة PostgreSQL.

## الحدود والاختلافات المتبقية

1. حفظ بيانات طريقة الدفع وعمليات المعرض عدة طلبات منفصلة، وليس معاملة واحدة تشمل النموذج كله. Backend يضمن أمان كل عملية؛ Admin يحتفظ بالخطوات المكتملة ويطلب المصالحة بعد انقطاع غير مؤكد. تحويل النموذج كله إلى حفظ ذري واحد يحتاج عقد Backend إضافياً.
2. صفحة اعتماد الشحن الحالية تدير standard وagent-admin. مسار via-agent اعتمادُه خاص بالوكيل في Backend؛ لا تضيف الواجهة زر اعتماد للأدمن مخالفاً لهذه الصلاحية.
3. الأرصدة المدينة المعروضة تقدير negative_balances_excluding_pending وليست ذمماً مؤكدة؛ هذا تعريف Backend وتوضيح الواجهة، لا اختلاف حسابي عالق.
4. الطرق القديمة الافتراضية USD تحتاج مراجعة العملة الصحيحة من الإدارة؛ لم تُجرَ إعادة تصنيف جماعية لبيانات حقيقية.
5. لم تُختبر جلسة تسجيل الدخول الثلاثية عبر SMTP/OTP أو اتصال موصل مزوّد حقيقي؛ التحقق التفاعلي استخدم حساب اختبار وتوكناته في قاعدة معزولة. صلاحيات المستخدم والأدمن وأخطاء API اختُبرت آلياً.
6. حجم بعض حزم البناء ما زال أكبر من 500 kB؛ تحذير أداء غير مانع للبناء، وليس خللاً في عقد API.
7. لا تعديل لـExpo في هذا العمل؛ التغييرات المتزامنة التي ظهرت تحت app/ محفوظة ومنفصلة.

## Git وما قبل النشر

- الفرع frontend-v2؛ التعديلات محلية وغير ملتزم بها، وتتضمن تغييرات سابقة ومتزامنة. لا Commit أو Push أو Merge أو Deploy.
- Stash: backup-before-stark-sync، والبصمة أثناء الاستكمال 7581fb6fb4c7bbc46773fdbfd0082d582339485d؛ بقي دون تطبيق أو حذف.
- لا استرجاع قسري أو git reset --hard، ولا حذف للتعديلات أو نسخ .bak.
- يلزم قبل النشر فقط: مراجعة diff النهائي واستثناء التغييرات المتزامنة غير التابعة للمهمة؛ موافقة صريحة على Commit/Push/Merge/Deploy؛ تأكيد إعدادات API للبيئة المقصودة وخطة migrations الخاصة بـBackend ومراجعة عملات طرق الدفع القديمة. لم يُنفذ أي إجراء نشر.
